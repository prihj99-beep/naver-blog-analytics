# 네이버 블로그 통계 · 로컬 대시보드

## 사용자용 로컬 대시보드

바탕화면의 **블로그 통계** 바로가기를 더블클릭하세요. `start_dashboard.bat`가 로컬 서버를 실행하고 기본 브라우저에서 `http://127.0.0.1:8765`를 엽니다. 다시 실행하면 같은 서버를 재사용합니다. 다른 프로그램이 포트를 사용 중이면 오류 창으로 안내하고 그 프로그램을 종료하지 않습니다.

1. 저장된 데이터는 로그인 없이 바로 조회할 수 있습니다. 조회 기간과 검색어·경로 필터를 적용하세요.
2. 수집 시작일·종료일을 선택하고 **네이버 통계 수집**을 누릅니다. 선택 날짜 확인 창에서 승인하면 Chromium이 열립니다.
3. Chromium에서 직접 로그인·CAPTCHA·추가 인증을 마친 뒤, 대시보드의 **로그인 완료 · 상태 확인**을 누릅니다. 이 버튼은 확인 요청이며 성공 선언이 아닙니다. 같은 비영구 세션에서 해당 블로그의 공식 통계 화면과 필수 다운로드 요소가 확인된 뒤에만 수집을 시작합니다.
4. 로그인 대기·사용자 인증 진행·확인 중·로그인 성공·수집 중·완료·취소·접근 제한을 구분합니다. 로그인 중 CAPTCHA는 직접 해결하도록 기다리며, 확인 실패 시 창을 유지하고 인증 대기로 돌아갑니다. 로그인 단계의 명시적 차단, 수집 중 새 보안 인증·접근 제한은 중단하며 자동 재시도하지 않습니다. 원문이나 인증 정보는 기록하지 않습니다.
5. **인증·수집 취소**는 현재 작업이 반환되면 저장 전에 취소합니다. 앞서 성공한 날짜와 기존 데이터는 유지됩니다. 이미 커밋 중이면 해당 커밋이 끝난 후 취소를 접수하고 다음 저장을 막습니다.
6. **프로그램 종료**는 수집 작업과 Chromium을 정리한 후 서버를 종료합니다. 다운로드 대기 중이면 종료까지 시간이 걸릴 수 있습니다. 기본 브라우저의 통계 페이지는 직접 닫아도 됩니다. 페이지 탭만 닫으면 서버는 계속 실행됩니다.

현재 DB는 `nekkorangkkerong` 블로그 전용입니다. 서로 다른 블로그의 데이터를 같은 DB에 섞지 않습니다. 서버는 **127.0.0.1에만** 바인딩합니다. 외부 페이지의 변경 요청을 차단하고, 변경 요청에는 메모리 내 페이지 토큰을 사용합니다. 별도 계정·비밀번호 설정은 필요하지 않습니다.

CSV는 현재 탭의 검색어 또는 상세 경로를, XLSX는 두 개의 독립 시트를 내보냅니다. 두 내보내기 모두 현재 조회 기간과 텍스트 필터를 적용합니다. 반복 등장은 원문이 같은 검색어가 나타난 **서로 다른 날짜 수**이며, 유입 횟수가 아닙니다. 비율은 날짜별 공식 백분율입니다. 아직 수집하지 않은 조회수는 표시하지 않습니다.

‘수집 안 함’은 DB에 성공한 보고서가 없는 날짜입니다. ‘수집 완료 · 검색어 없음’은 날짜·종류·헤더 검증을 통과한 파일에 검색어가 없는 날짜입니다. 실패한 날짜를 검색어 0개로 저장하지 않습니다. 실제 데이터가 없는 날짜의 공식 파일은 아직 확보하지 못했으며, 이 구분은 합성 파일로 검증했습니다.

시작 시 기존 SQLite를 `data/backups/YYYY-MM-DD-before-dashboard.sqlite3`에 하루 한 번 백업합니다. 대시보드 조회와 시작·종료는 기존 통계 행을 수정하지 않습니다.

바로가기가 없거나 프로젝트 위치를 바꿨다면 `create_shortcut.ps1`을 실행해 생성할 수 있습니다. 기존 같은 이름 바로가기는 덮어쓰지 않습니다. 진단용 직접 실행:

```powershell
.\.venv\Scripts\python.exe -m analytics.dashboard
```

브라우저 UI 회귀 검증(대시보드 실행 상태, 로컬 화면만 테스트):

```powershell
$env:BLOG_UI_TEST = '1'
.\.venv\Scripts\python.exe -m unittest discover -s tests -v
```

UI 테스트는 초기 두 날짜·7개 검색어 기준입니다. 네이버 로그인이나 수집은 하지 않습니다. 실제 수집 실패와 미검증 범위는 [DASHBOARD_RESULTS.md](DASHBOARD_RESULTS.md)를 참고하세요.

로그인 상태 관리 개선 검증과 실제 사용자 검증 절차는 [LOGIN_STATE_RESULTS.md](LOGIN_STATE_RESULTS.md)를 참고하세요. 기본 테스트 실행에도 모의 인증 화면·상태 경쟁·모의 대시보드 테스트가 포함됩니다. 이 테스트의 모든 네이버 형식 URL은 브라우저 라우트에서 가로채며 외부 요청을 보내지 않습니다.

Python 3.12 + Playwright. 네이버의 공식 **유입분석 → 일간 → 검색 유입** XLSX를 다운로드합니다. 로그인은 Chromium 창에서 직접 수행하며, 비밀번호·쿠키·인증 헤더·storage state를 저장하거나 로그로 출력하지 않습니다. 브라우저는 비영구 컨텍스트를 사용하고 종료 시 닫습니다.

## 실행 (PowerShell, 프로젝트 폴더)

```powershell
.\.venv\Scripts\python.exe -m analytics collect --blog-id YOUR_BLOG_ID --dates 2026-10-12 2026-10-15
.\.venv\Scripts\python.exe -m analytics export --output exports
```

날짜 목록을 확인한 뒤 `YES`를 입력하고, 열린 창에서 직접 로그인한 후 터미널에서 Enter를 누릅니다. 기존 Chromium만 사용하며 찾지 못하면 `--chromium C:\path\to\chrome.exe`로 지정합니다. 자동 브라우저 설치는 하지 않습니다.

기간 수집도 지원하지만 **현재 실제 네이버 수집 승인은 2026-10-12와 2026-10-15 두 날짜에 한정**됩니다. 아래 기간 명령은 별도 승인 후 실행하세요.

```powershell
.\.venv\Scripts\python.exe -m analytics collect --blog-id YOUR_BLOG_ID --start 2026-10-12 --end 2026-10-15
```

날짜 사이 기본 간격은 3초이며 `--delay`로 늘릴 수 있습니다. 날짜당 한 번 다운로드하며 실패하면 재시도 없이 멈춥니다. CAPTCHA, 접근 제한 문구, HTTP 401/403/429 또는 예상하지 못한 대화상자 발생 시 중단합니다. 우회는 하지 않습니다.

## 데이터

- `data/analytics.sqlite3`: 날짜 메타데이터와 독립적인 `keyword` / `route` 목록. 날짜 재수집 시 해당 날짜만 트랜잭션으로 교체합니다.
- `downloads/search-inflow-YYYY-MM-DD.xlsx`: 검증을 통과한 공식 원본.
- `exports/keywords.csv`, `exports/routes.csv`: UTF-8 BOM CSV. 날짜, 통계 종류, 단위, 선택항목, 순서, 원문, 비율을 포함합니다.
- 비율은 공식 파일의 백분율 수치를 문자열로 보존합니다. 횟수를 역산하지 않습니다. 같은 XLSX 행에 있는 두 목록을 연결하지 않습니다.
- 워크시트 dimension 대신 실제 셀을 읽습니다. 날짜·종류·헤더·비율을 검증한 후 저장합니다. 다운로드·파싱 실패 시 기존 DB를 유지합니다. 검증된 헤더만 있고 검색어 행이 없으면 수집된 빈 날짜로 저장합니다.
- CSV는 원문을 보존하므로 외부 문서나 웹 페이지에 표시할 때 해당 환경의 출력 이스케이프를 적용하세요.

## 기존 XLSX 가져오기 / 테스트

```powershell
.\.venv\Scripts\python.exe -m analytics import-xlsx verification/search-inflow-2026-10-12.xlsx verification/search-inflow-2026-10-15.xlsx
.\.venv\Scripts\python.exe -m unittest discover -s tests -v
```

기간 수집 테스트는 합성 XLSX로 수행하며 네이버에 접속하지 않습니다. 조회수 수집과 콘텐츠대장 연동은 포함하지 않습니다. DOM 선택자나 공식 파일 형식이 바뀌면 안전하게 실패할 수 있습니다. 블로그 한 개당 DB 파일 하나를 사용하세요 (`--db`는 하위 명령 앞에 지정).
