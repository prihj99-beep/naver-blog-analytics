# 8766 주간 분석 1차 구현 결과

## 구현 범위

기존 주간 통계 탭에서 붙여넣기 후 자동 미리보기, 확인 저장 후 자동 분석 표시를 추가했습니다.
자료 상태 → 이번 주 변화 → 검색어 주제 분석 → 콘텐츠 검토 후보 → 트렌드 비교 순서입니다.
새 분석 버튼·엑셀 업로드·AI API 키는 필요 없습니다. 기존 수동 미리보기·교체 확인·엑셀 다운로드는 유지합니다.

- 조회수는 회수 차이, 검색 유입률은 %p 차이로 표시합니다. 미등록·누락은 0으로 만들지 않습니다.
- 기존 comparisons()를 재사용하고 화면에서는 신규 관측·반복·이번 목록에서 미확인으로 설명합니다.
- 고정 표현 규칙 및 현재 주제군 구성어와의 공백 제외 일치로 분류 후보와 근거를 표시합니다. 원문·개별 비율을 보존하고 합산하지 않습니다.
- 복수 후보·미분류를 구분하고 관측 검색어에 근거한 질문 템플릿만 콘텐츠 검토 후보로 보여 줍니다.
- 모든 콘텐츠 후보에 기존 글 중복·실제 질문 의도·최신성의 확인 필요사항을 표시합니다.
- 현재 화면의 트렌드 결과만 재사용하며 기간·조회 당시 구성어·버전을 명시합니다. 구성어 일치와 관련 주제를 구분합니다.
- 기간이 맞지 않으면 비교 보류, 메모리 결과가 없거나 만료되면 기본 분석만 표시합니다. API 자동 호출·재시도는 없습니다.

## 자료 상태와 DB 보호

- 기본 상태는 미확인입니다. 전체는 사용자 확인이며 프로그램의 전체성 검증이 아닙니다.
- 독립된 더보기/더 보기/해당 Markdown 링크가 남으면 전체 선택보다 우선하여 불완전 가능성을 표시합니다.
- 원문을 새로 입력하면 이전 전체 확인을 이어받지 않고 미확인으로 되돌립니다.
- 명시적 저장 시 기존 weekly_reports.report_json에 coverage/has_more/effective_coverage만 함께 기록합니다. 새 테이블·열·DB·분석 이력을 만들지 않습니다.
- 기존 보고서에 새 필드가 없으면 미확인으로 읽고, 마이그레이션·자동 재저장은 하지 않습니다.
- 같은 원문이라도 범위 표시를 바꾸면 기존 교체 확인과 버전 검증을 거쳐 새 버전으로 보존합니다.
- 기존 DB·8765 소스·다운로드 원본 XLSX의 SHA256은 작업 전후 동일합니다. 테스트는 임시 DB만 사용했습니다.

## 실제 사용

1. 현재 8766의 트렌드 결과를 보존해야 한다면 먼저 기존 내보내기를 사용합니다. 서버 재시작 시 메모리 결과는 사라집니다.
2. 기존 분석 서버를 종료하고 start_keyword_analysis.bat로 다시 실행합니다. 주간 기능에는 API 키가 필요 없습니다.
3. 주간 통계 탭에 직접 복사한 텍스트를 붙여넣습니다. 자동 미리보기를 확인합니다.
4. 필요할 때만 목록 범위를 선택합니다. 기본 미확인으로도 저장·기본 분석이 가능합니다.
5. 확인한 주간 자료 저장을 누르면 해당 주간의 분석으로 이동합니다. 별도 분석 실행이나 엑셀 전달은 필요 없습니다.

## 남은 한계

- 규칙은 제한된 표현에만 적용되며 실제 검색 의도를 이해한 AI 분석이 아닙니다. 규칙·현재 주제군이 바뀌면 재계산 결과도 바뀝니다.
- 목록 전체성·비율 분모·데이터 없음 문구의 하위 영역은 추정하지 않습니다. 실제 일반 텍스트 복사본 검증은 추가로 필요합니다.
- 채널 조회수 30회 미만의 경고는 표시용 보수적 기준이며 통계적 유의성 기준이 아닙니다.
- 콘텐츠대장·게시물 연결 통계가 없어 특정 글의 보완이나 발행 필요성을 판단하지 않습니다.
- 신규 관측을 수요 증가로, 두 지표의 동반 변화를 인과관계나 콘텐츠 효과로 해석하지 않습니다.
