# B: 누적 자료와 ChatGPT 분석 환류 — 승인 전 설계

이 문서는 설계만 제시합니다. 이번 작업에서는 B의 DB·내보내기 형식 변경·JSON 가져오기·실행 상태 기능을 구현하지 않습니다.
원본 통계는 사실 자료, 외부 분석은 검토할 의견, 실행 기록은 사용자가 확인한 사실로 구분합니다.

## 1. 현재 엑셀 확인 결과

실제 저장된 3주(2026-09-28~10-18)의 최신 보고서는 각각 v1이고, 검색어는 4+4+12=20행입니다. 복사 범위는 모두 미확인입니다.
실제 DB를 읽기 전용으로 조회하고, XLSX를 메모리에서 생성해 개수·중복·필드를 검증했습니다. 실제 파일이나 운영 DB를 수정하지 않았습니다.

| 시트 | 현재 포함 정보 | 현재 범위/한계 |
|---|---|---|
| 실제 유입 검색어 | 일별 날짜·원문·비율·원본 순서·원본 해시 | 선택 종료일까지 14일. 주간 누적과 별도 |
| 검색 트렌드 | 기간·일간/전체 조건·조회 시각·주제군명/버전/구성어·일별 상대지수·누락 상태 | 현재 조회 결과 한 건. 과거 조회 이력 없음 |
| 주제군 및 수집상태 | 현재 저장 주제군·조회 당시 주제군·일별 수집/검색어 없음/미수집 | 주간 전체 범위와 동일하다고 해석하면 안 됨 |
| 주간 유입검색어 원자료 | 시작/종료·채널·저장 버전·조회수·검색 유입률·검색어·개별 비율·상세 URL·출처·저장 시각·원문 해시 | 저장된 전체 주간의 최신 버전. 20행 중복/누락 없음 |
| 주간 요약 및 출처 | 기간·조회수·검색 유입률·행 수·이전 주 존재·실효 목록 상태·사용자 선택·더보기 | 3주 모두 미확인. 상태는 원자료와 기간으로 연결 |
| 주간 검색어 비교 | 현재/이전 기간·검색어·목록 상태·각 비율·차이(%p) | 직전 주 미등록 구분. 정확한 원문 기준 |

현재 보유한 최신 주간 통계의 비교에는 필요한 값이 들어 있습니다. 다음은 아직 없습니다.

- 이전에 교체된 보고서 버전 전체, 복사 원문 전체: 현재 XLSX에는 제외. 원문 버전은 weekly_sources에 별도 보존되어 있음.
- 파일 전체를 식별하는 내보내기 ID와 검증용 자료 명세, 개별 근거 행 ID.
- 장기 트렌드 조회 이력, 방문자 수·정확한 검색 유입 횟수·검색어별 게시물 연결·콘텐츠대장.
- 기본 브리핑 및 외부 분석·실행 기록: 현재 내보내기에 포함되지 않음.

따라서 ‘누적 전체’는 모든 수집 원문 버전이나 모든 트렌드 조회가 아니라 **현재 저장된 주간별 최신 통계 전체**입니다.

## 2. 다음 승인 후 보완할 내보내기 명세

기존 XLSX를 유지하고 `분석 요청 정보` 시트를 추가하는 방식이 최소 변경입니다.

- export_id, dataset_id, schema_version, 생성 시각(시간대 포함).
- 각 시트의 자료 범위. 주간 전체 기간과 일간 14일, 트렌드 한 조회의 기간을 별도 표기.
- 기간별 report_ref = 채널/시작/종료, revision, source_hash, saved_at, 사용자 범위, 실효 범위, 더보기 유무.
- record_ref = report_ref + revision + 검색어 원문의 결정적 식별값. 비슷한 검색어로 합치거나 정규화한 문자열로 식별하지 않음.
- 채널이 미확인인 기존 보고서는 미확인으로 유지하고 로컬 자료집합 ID+기간으로 식별합니다. 다른 블로그 자료와 임의로 합치거나 채널명을 추정하지 않습니다.
- 누락 주와 이전 주 미등록, 일부/미확인 복사 목록을 분리. 없는 수치를 0으로 채우지 않음.
- 트렌드는 조회 시각·조건·그룹 버전·상대지수라는 의미를 유지. 조회되지 않은 과거 결과를 만들지 않음.

내보내기 당시 주간 값과 범위 메타데이터를 별도 환류 저장소의 변경 불가능한 snapshot으로 보존하면, 나중에 원문을 교체해도 어떤 자료로 분석했는지 확인할 수 있습니다.
원본 통계 DB에는 쓰지 않습니다. 트렌드 전체의 장기 저장은 이번 설계의 자동 처리 대상이 아니며 별도 범위 결정이 필요합니다.
추가 시트·snapshot 기록도 이번에는 구현하지 않습니다.

## 3. 제안하는 JSON 교환 형식

아래는 형식 예시이며 실제 분석 기록이 아닙니다. 내보내기 명세의 ID와 근거 참조를 ChatGPT에 그대로 사용하도록 요청합니다.

```json
{
  "schema_version": "1.0",
  "timezone": "Asia/Seoul",
  "analysis_as_of": "2026-10-19",
  "source_dataset_id": "내보낸 파일에 표시된 dataset_id",
  "source_period": {"start": "2026-09-28", "end": "2026-10-18"},
  "title": "3주간 블로그 검색 유입 검토",
  "findings": [
    {
      "id": "finding-1",
      "text": "수표와 입찰 서류 관련 질문을 점검할 만합니다.",
      "evidence_refs": ["명세에 있는 record_ref"],
      "limitations": ["검색어를 모두 복사했는지 확인되지 않았습니다."]
    }
  ],
  "recommendations": [
    {
      "id": "recommendation-1",
      "kind": "content_review",
      "title": "수표 준비 설명을 기존 글에서 점검",
      "reason": "실제 검색어에서 확인된 질문을 기존 설명과 대조하기 위한 검토 후보입니다.",
      "evidence_refs": ["명세에 있는 record_ref"],
      "checks": ["이미 발행한 글에서 다룬 내용인지 확인"],
      "suggested_status": "review"
    }
  ],
  "questions": ["목록 전체를 복사했나요?"],
  "limitations": ["조회수 변화의 원인을 특정 콘텐츠에 귀속할 수 없습니다."]
}
```

- kind는 content_review/followup_candidate. 자동 글쓰기·발행 명령은 없음.
- 상태 키는 review/in_progress/completed/on_hold, 화면은 검토 전/진행 중/완료/보류.
- 가져온 suggested_status는 외부 분석의 제안이며 실행 사실이 아님. 기본 로컬 상태는 검토 전, 다른 상태 반영에는 사용자의 명시적 확인 필요.
- 앱이 고유 import_id와 작업 ID를 발급. 외부 JSON의 ID로 기존 기록을 UPDATE하지 않음.
- 외부 id는 해당 JSON 안에서만 참조하며 중복을 거부. 같은 JSON 재가져오기는 해시로 안내하고 중복 저장하지 않는 방식을 권장.
- 형식 검증은 날짜·타입·허용 상태·중복 ID·자료 범위·근거 참조·dataset_id 일치 등을 확인. 알 수 없는 필드와 과도한 크기(예: 1MB 초과)는 거부.
- JSON의 문장 자체가 사실이라는 보증은 할 수 없음. 근거와 해석을 함께 미리보기하고 ‘외부 분석 · 사용자 검토 필요’로 표시.
- API 키·쿠키·인증 헤더는 교환 형식에 없음. JSON을 코드로 실행하지 않고, HTML은 텍스트로만 표시하며 외부 URL을 자동 방문하지 않음.

기존 XLSX에는 dataset_id가 없으므로 과거 파일의 참조를 자동 검증할 수 없습니다.
초기 구현에서는 새 명세로 내보낸 자료를 기본 지원하고, 기존 파일은 사용자가 자료 기간을 연결하더라도 ‘자료 연결 미검증’으로 구분해야 합니다.

## 4. 원본과 분리한 저장 구조 제안

새 파일 `data/analysis-feedback.sqlite3`를 **향후 승인된 구현에서만** 만듭니다. 기존 통계·주제군 DB에는 쓰지 않습니다.

| 테이블 제안 | 역할 |
|---|---|
| export_snapshots | dataset/export ID, 명세·해시, 당시 주간 값·버전·복사 상태. 변경 불가 |
| analyses | 앱 발급 import ID, 기준일·자료 범위·snapshot 참조, 검증된 원본 JSON·해시·가져온 시각. 변경 불가 |
| recommendations | 외부 추천 ID와 앱 작업 ID 연결, 원래 추천·근거·확인사항·baseline 참조. 기존 추천 덮어쓰기 금지 |
| action_events | 작업 ID, 사용자가 선택한 상태·변경 시각·실제 작업일·메모. 상태 변경을 추가 기록 |

다른 내용으로 재분석하면 새 analyses 행으로 보존합니다. 기존 분석을 수정하려면 새 개정 분석으로 연결하며 이전 기록을 남깁니다.
현재 실행 상태는 마지막 이벤트에서 읽습니다. ‘완료’도 실제 작업일을 직접 확인하며, AI가 출력한 날짜를 실행 사실로 자동 확정하지 않습니다.
원본 통계가 바뀌면 snapshot과 현재 버전의 차이를 표시하고, 분석 당시 자료를 현재 값으로 바꿔치기하지 않습니다.

## 5. 가져오기와 실행 계획 화면 제안

기본 주간 브리핑은 그대로 두고 별도 `ChatGPT 분석` 영역을 추가합니다(이번에는 미구현).

1. 기존 XLSX 내보내기 → ChatGPT에 파일과 JSON 반환 형식 전달(사용자 수동).
2. JSON 파일 선택 또는 붙여넣기 → 검증. 자동 저장 없음.
3. 분석 기준일·기간·근거 자료 버전·목록 상태·주요 발견·추천·확인사항을 미리보기.
4. 잘못된 근거 ID/자료 기간/중복은 오류, 이후 수정된 통계는 ‘이전 버전 기준’ 안내. 원본 자료와 다른 값으로 자동 보정하지 않음.
5. 사용자가 확인 저장 → 분석 이력과 검토 전 작업 목록 표시.
6. 사용자가 작업 상태·실제 작업일·메모 변경. 실행 기록은 분석 원문과 분리.

검증 실패·취소·중복·저장 실패는 기존 분석 및 통계에 영향을 주지 않아야 합니다.

## 6. 이후 데이터와 연결

- 추천이 참조한 baseline snapshot과 검색어 원문/주제 참조를 보존.
- 사용자가 실제 작업일과 확인할 전후 주간을 선택. 미등록 주를 건너뛰어 임의로 ‘전주’로 쓰지 않음.
- 이후 조회수·검색 유입률·해당 검색어의 목록 등장·원래 비율을 나란히 표시.
- 전후 기간의 복사 범위·누락 주·보고서 수정 여부·다른 작업 여부를 함께 표시.
- 실행일을 모르면 전후 구분을 하지 않음. 작업이 주중에 수행되면 그 주가 혼합 기간임을 안내.
- ‘완료 후 이런 변화가 보였다’까지만 설명하고 해당 추천의 성과·인과관계·예상 수익을 단정하지 않음.
- 비교 결과는 저장 통계와 실행 이벤트에서 계산. 불필요한 효과 점수 DB는 만들지 않음.

## 7. 승인 후 단계별 구현

1. **자료 식별**: 기존 내보내기 유지 + 명세/ID·snapshot 추가, 누락·버전·범위 검증 테스트.
2. **가져오기**: JSON 검증·미리보기·명시적 저장·중복 방지·분리 DB, 기존 자료 불변 테스트.
3. **실행과 비교**: 네 가지 상태 이벤트·실제 작업일·전후 기간 선택, 인과관계 단정 없는 비교 화면.

각 단계는 임시 DB·모의 JSON·브라우저로 검증하고 원본 DB 해시 불변을 확인합니다. 외부 AI API 호출과 8765 자동 수집은 추가하지 않습니다.

## 8. 구현 전 결정할 사항

- 새 명세로 내보낸 자료만 정식 가져오기로 지원할지, 기존 XLSX의 미검증 수동 연결도 허용할지.
- 장기 외부 분석의 기준 자료를 최신 주간 버전만으로 할지, 과거 수정 버전도 선택하게 할지.
- JSON의 suggested_status는 기본 검토 전으로 둘지, 사용자가 별도로 상태를 확인해 가져오게 할지.
- snapshot을 저장할 범위와 백업 방식. 현재 트렌드 한 건을 넘어서는 장기 보관은 별도 승인 범위로 구분.

권장 최소안은 새 명세·최신 버전 주간 snapshot·초기 검토 전 상태이며, 원본 통계와 현재 브리핑은 계속 독립적으로 유지합니다.
