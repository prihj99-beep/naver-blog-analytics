작업 기준일: 2026-10-19. **구현은 완료했으나 실제 Chromium·로컬 HTTP·BAT 실행 검증은 아직 완료하지 못했습니다.** 자동 승인 검토 서비스가 모델 처리 용량 부족으로 실행 요청을 처리하지 못했습니다. 안전성 거부 판정은 아니며, 사용자 요청대로 동일 승인 경로로 재시도했으나 실행되지 않았습니다. 승인 절차를 우회하지 않았습니다.

실제 NAVER API HUB 요청·실제 키 입력·로그인·수집·Git commit/push는 하지 않았습니다.

## 2. 화면 구성·사용 방법

기존 분석 서버를 종료하고 `start_keyword_analysis.bat --demo`로 화면만 확인할 수 있습니다. 탭만 닫는 것은 서버 종료가 아닙니다. 이번 변경분은 아직 Chromium 실행 검증을 마치지 않았으므로 확인 중 문제가 있으면 실제 API 조회는 진행하지 마세요.

- **검색 트렌드**: 기본 탭. 저장된 주제군을 선택하고 검색어·버전을 확인한 뒤 종료일을 선택합니다. 차트·일별 표·7일 비교·조회 상태·오류를 표시합니다.
- **내 블로그 유입어**: 기간·필터로 기존 DB를 읽기 전용 조회합니다. 추가할 주제군을 고른 뒤 행의 추가를 누르면 관리 탭의 편집안으로 이동합니다. **저장해야 DB에 반영**됩니다.
- **주제군 관리**: 생성·수정·삭제와 버전을 관리합니다. 검색어는 한 줄에 하나이며 줄을 지워 삭제합니다. 저장 후 세 탭의 관련 목록이 갱신됩니다. 예시는 별도 접힘 영역에만 두고 입력란은 비워 둡니다.

주제군 없음·선택 없음·정상 모드의 키 없음·날짜 오류·처리 중에는 조회 버튼을 비활성화하고 이유를 표시합니다. 데모에서는 키 없이 모의 조회합니다. 탭 이동·주제군 저장·유입어 조회로 API를 호출하지 않습니다.

## 3. 인증정보 입력·실행

1. 기존 분석 화면의 **분석 화면 종료**를 누릅니다. 기존 블로그 통계 수집기는 종료할 필요가 없습니다.
2. `start_keyword_analysis_secure.bat`를 더블클릭합니다.
3. 콘솔이 요청하는 Client ID와 Client Secret을 입력하고 각각 Enter를 누릅니다. **글자와 별표가 보이지 않아도 정상**입니다.
4. 브라우저의 키 설정 확인 문구를 확인합니다. 이는 키를 읽었다는 뜻이며 실제 인증 성공을 의미하지 않습니다.
5. 실제 API 조회 승인 전에는 조회 버튼을 누르지 않습니다.

이미 설치된 Python의 Windows `getpass`를 사용하므로 PowerShell 실행 정책 변경·관리자 권한·추가 설치가 필요 없습니다. 기존 환경변수 이름으로 같은 프로세스에 전달하며, 명령행 인자·파일·BAT·소스·Git·로그·브라우저 JavaScript에 키를 넣지 않습니다. 서버는 브라우저를 열기 전에 자기 환경변수에서 키를 제거합니다. 취소·오류·종료 때도 실행기에서 정리합니다.

실행 중인 서버가 있으면 키가 새 서버에 적용되지 않는 혼동을 막기 위해 먼저 종료하도록 안내합니다. 숨김 입력을 보장할 수 없는 파이프·리다이렉션·일반 에코 fallback에서는 중단합니다. 기존 PowerShell 환경변수 입력 방식도 README의 대안으로 유지했습니다.

기존 수집기 18개 회귀 테스트는 XLSX 파서·독립 목록·재실행·실패/취소 보존·트랜잭션·조회/내보내기·빈 날짜 구분·임시 DB 백업·모의 로그인 작업 경쟁 상태·저장된 공식 파일 대조입니다. 실제 로그인·다운로드는 하지 않았습니다.

전체 신규 테스트는 46개로 구성됩니다. 이번에는 네트워크/브라우저 실행이 필요 없는 29개만 실행됐습니다. **나머지 17개를 통과로 간주하지 않습니다.** 이전 버전의 화면 테스트 통과 기록을 이번 탭 화면 검증 결과로 재사용하지 않습니다.

남은 검증 명령은 README에도 있습니다.

```powershell
.\.venv\Scripts\python.exe -B -m unittest keyword_analysis.test_analysis keyword_analysis.test_secure_launch keyword_analysis.test_ui -v
```

첫 명령은 실제 API 대신 모의 객체를 사용합니다. 두 번째 명령의 기존 `BLOG_UI_TEST=1` 선택 실행 항목은 기존 대시보드가 별도로 필요하며 기본적으로 제외됩니다.

## 6. 실제 API 최초 조회 — 별도 승인 후

이번 모의 화면/실행 검증이 끝난 뒤 사용자 승인 시에만 진행합니다.

1. API HUB의 검색어 트렌드 권한·요금·한도를 확인합니다.
2. 안전 실행 BAT로 실제 키를 콘솔에 숨김 입력합니다.
3. 정상 모드의 키 설정 확인 문구를 확인합니다.
4. 검색 트렌드 탭에서 경매 입찰 준비와 기준 종료일을 선택합니다.
5. 승인된 시점에 **검색 트렌드 조회를 한 번** 누릅니다. 인증·권한·한도 오류에는 자동/반복 재시도하지 않습니다.

## 7. 남은 위험·확인 필요

- 승인 검토 서비스 오류로 남은 실행 테스트를 마쳐야 합니다. 이를 완료 검증으로 보고하지 않습니다.
- 실제 Windows 콘솔에서의 숨김 입력·Explorer 더블클릭·기본 브라우저 자동 열기 확인이 필요합니다.
- 숨김 입력은 에코 차단입니다. 평문 키가 실행 중 프로세스 메모리·일시적 환경변수에 존재하며, 문자열 참조 제거가 메모리 복사본 덮어쓰기를 보장하지 않습니다. 동일 사용자/관리자·악성코드·키로거·덤프·스왑·클립보드 기록을 완전히 차단하지 않습니다.
- 실제 API 인증, 통계 확정 시점·저검색량 기준·현재 과금 조건은 미확인입니다.
- 블로그 검색 API·결과 영구 보관·기존 대시보드 통합은 이번 범위가 아닙니다.

현재 상태는 **코드 구현 완료 / 단위·오프라인 회귀 통과 / 실제 화면·실행 검증 보류 / 실제 API 호출 보류**입니다.
