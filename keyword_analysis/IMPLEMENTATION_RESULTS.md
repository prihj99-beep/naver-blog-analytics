# 검색어 트렌드 1차 구현 결과

검증일: 2026-10-19. 실제 네이버 API 호출·로그인·통계 수집·Git commit/push는 수행하지 않았습니다.

## 1. 생성·수정 파일

기존 소스 파일을 수정하지 않고 아래 파일을 추가했습니다.

- `keyword_analysis/__init__.py`, `__main__.py`: 독립 모듈 진입점
- `keyword_analysis/model.py`: 별도 주제군 DB, 버전 충돌 검사, 기존 유입어 읽기 전용 조회
- `keyword_analysis/trends.py`: 공식 API HUB 클라이언트, 응답 검증, 동일 응답의 14일 비교
- `keyword_analysis/server.py`: 127.0.0.1 전용 서버, 보안 검사, 요청 제한, 실행·종료·명시적 데모 모드
- `keyword_analysis/web/index.html`, `app.js`, `style.css`: 독립 분석 화면
- `keyword_analysis/test_analysis.py`, `test_ui.py`: 모의 단위·HTTP·Chromium·Windows BAT 테스트
- `keyword_analysis/README.md`: 실행·키 설정·계산·제약 안내
- `keyword_analysis/IMPLEMENTATION_RESULTS.md`: 이 보고서
- `start_keyword_analysis.bat`: 별도 실행 파일
- `data/keyword-analysis.sqlite3`: 새 주제군 DB. 현재 주제군 0개, API 결과 없음
- `verification/keyword-analysis-demo.png`: 모의 데이터 화면 검증 이미지

패키지 추가 설치와 `requirements.txt` 변경은 없습니다.

## 2. 실행 방법

프로젝트 루트의 `start_keyword_analysis.bat`를 실행하면 기본 브라우저로 `http://127.0.0.1:8766/`을 엽니다. 서버가 실행 중이면 동일 프로젝트·모드 확인 후 재사용합니다. 별도 분석 서버만 종료하는 버튼이 있습니다.

실제 API 호출 없이 화면을 확인할 때는 PowerShell에서 `./start_keyword_analysis.bat --demo`를 사용합니다. 데모 배너와 모의 데이터 표기가 표시됩니다. 기본 모드와 동시에 실행하려면 `--port 8767`을 지정합니다. 데모 역시 주제군 저장은 신규 주제군 DB에 반영합니다.

BAT는 실제 `cmd.exe`를 통한 시작·중복 실행·종료를 검증했습니다. 기본 브라우저 자동 열기는 호출 지점을 모의 처리해 URL과 1회 실행을 검증했습니다. 실제 Explorer 더블클릭과 사용자의 기본 브라우저 프로필에서의 자동 열기는 사용자 확인이 남아 있습니다.

## 3. 구현 기능·미구현 기능

구현:

- 주제군 생성·수정·삭제, 검색어 1~5개, 현재 버전 표시 및 이전 버전 보존
- 조회당 주제군 최대 5개, 오래된 버전 요청 거절
- 기존 유입어 날짜·문자열 필터, 원문을 주제군 작성란에 추가
- 미수집 날짜와 수집했으나 검색어가 없는 날짜 구분
- 공식 검색어 트렌드 POST 클라이언트, HTTPS 인증 헤더, 고정 엔드포인트
- 일간 14일 응답의 앞·뒤 7일 평균, 지수 차이, 조건부 변화율
- SVG 차트, 누락 지점의 선 끊기, 날짜별 표, 상대지수 안내
- 0·작은 분모·그룹/날짜 누락·메타데이터 불일치·비정상 응답 처리
- 키 미설정, 인증/권한 오류, 한도 초과, 연결 실패/타임아웃 구분
- 자동 호출·자동 재시도 없음, 단일 동시 요청, 최소 2초 요청 간격
- 결과 영구 저장·브라우저 저장소 사용 없음, no-store 헤더, 새 조회 시 이전 결과 폐기
- 종료 중 늦은 응답 무시, Windows 포트 독점 및 서버 중복 실행 방지

제외:

- 블로그 검색 API, 장기 결과 저장·CSV/XLSX 내보내기
- 기존 대시보드와의 화면·실행 통합, 기존 수집기·로그인 변경
- 주간/월간 조회 및 기기·성별·연령 세부 필터. 현재 전체 조건의 일간 14일 비교
- Windows 자격 증명 관리자 연동. 이번에는 실행 환경변수 방식 지원
- 자동 글쓰기·발행, 실제 API 검증

auction-agent 및 외부 저장소는 수정하지 않았습니다. Git commit/push도 하지 않았습니다.

## 6. 실제 API 사용을 위한 준비

NAVER API HUB에서 검색어 트렌드 권한을 가진 Client ID와 Client Secret을 발급받고, README의 비밀 입력 방식으로 실행 환경변수를 설정합니다.

- `NAVER_API_HUB_CLIENT_ID`
- `NAVER_API_HUB_CLIENT_SECRET`

키를 BAT·소스·Git·로그·대화에 넣지 않습니다. 서버는 시작 시 키를 메모리에 읽고 브라우저 실행 전에 자기 프로세스 환경변수에서 제거합니다. 키를 바꾸면 기존 분석 서버를 종료하고 다시 실행해야 합니다. 이번에는 실제 키를 사용하지 않았습니다.

## 7. 남은 확인

- 실제 계정 인증·API 권한·실제 응답 호환성·한도·요금 조건은 아직 미검증입니다.
- 그룹당 검색어 수는 공식 자료 간 5개/20개 차이가 있어 5개로 제한했습니다.
- 최신 데이터 확정 시각과 저검색량 처리 기준은 미확인입니다. 어제 이전 날짜라고 확정된 통계라고 보장하지 않습니다.
- 평균 1 이하의 변화율 숨김은 공식 기준이 아닌 UI 기준입니다.
- 사용자 PC의 기본 브라우저와 Explorer 더블클릭 동작은 최종 사용자 확인이 남아 있습니다.
- 프로세스 메모리·운영체제 스왑/크래시 덤프를 완전히 격리하는 기능은 아닙니다.
- API 결과 영구 보관·블로그 검색·기존 화면 통합은 추후 별도 승인 대상입니다.
