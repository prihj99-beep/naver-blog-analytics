# 검색어 트렌드 분석 — 탭 화면과 안전 실행

기존 `analytics/` 수집기와 독립적으로 실행합니다. 기존 Python 가상환경과 표준 라이브러리만 사용하므로 추가 설치는 없습니다. Playwright 수집·로그인·블로그 검색 API는 변경하지 않습니다.

## 화면만 먼저 확인하기 — 실제 API 호출 없음

기존 분석 서버가 실행 중이면 그 화면의 **분석 화면 종료**를 누르세요. 탭만 닫으면 서버는 계속 실행됩니다. 이 종료는 기존 블로그 통계 수집기에 영향을 주지 않습니다.

프로젝트 폴더의 PowerShell에서:

```powershell
.\start_keyword_analysis.bat --demo
```

모의 응답 전용 배너를 확인하세요. 데모에서는 키를 입력하거나 사용하지 않습니다. 주제군을 저장하면 기존과 같은 주제군 DB에 저장되므로 사용자가 저장한 `경매 입찰 준비`도 그대로 보입니다. 구현 테스트는 임시 DB에서 진행하며 실제 사용자 주제군을 수정하지 않습니다.

기본 주소는 `http://127.0.0.1:8766/`입니다. 다른 포트가 필요하면 `--port 8767`을 붙입니다.

## 목적별 4개 탭

검색 트렌드·내 블로그 유입어·주제군 관리를 유지하고 **주간 통계** 탭을 추가했습니다. 주간 입력·저장·내보내기는 아래 ‘크리에이터 어드바이저 주간 통계’ 안내를 참고하세요.

### 검색 트렌드 — 기본 탭

저장된 주제군 1~5개를 선택하면 선택한 주제군의 검색어와 버전을 보여 줍니다. 기준 종료일을 고르고 **검색 트렌드 조회**를 누릅니다. 날짜별 차트·표, 이전 7일/최근 7일 평균, 지수 차이·조건부 변화율, API 상태·오류를 이 탭에서 확인합니다.

다음 조건에서는 버튼을 비활성화하고 이유를 표시합니다.

- 주제군 없음: **주제군을 먼저 등록하세요**
- 선택 없음: **분석할 주제군을 선택하세요**
- 정상 모드에서 키 없음: **API 인증정보를 설정하세요**
- 유효하지 않은 종료일, 상태 확인 중, 저장/조회/종료 처리 중

데모 모드에서는 인증정보 없이 모의 조회할 수 있습니다. 탭 전환·화면 열기·주제군 저장·기존 유입어 조회만으로 API를 호출하지 않습니다. 조회 중에는 버튼과 편집 기능을 잠가 중복 요청을 방지합니다. 자동 재시도하지 않습니다.

### 내 블로그 유입어

기간·원문 필터로 저장된 유입어를 조회합니다. **추가할 주제군**에서 저장된 주제군 또는 새 주제군 작성란을 고르고, 검색어 행의 **추가**를 누르면 **주제군 관리** 탭의 편집안으로 이동합니다. 확인 후 **주제군 저장**을 눌러야 실제 반영됩니다. 저장하지 않은 다른 편집안이 있으면 버릴지 확인합니다.

실제 유입 비율은 내 블로그의 날짜별 통계이고 데이터랩 상대지수는 검색 관심도입니다. 두 지표를 합치거나 방문자 수·절대 검색량을 추정하지 않습니다. 미수집 날짜와 수집했으나 검색어가 없는 날짜를 구분합니다.

### 주제군 관리

주제군 이름과 검색어를 직접 입력합니다. **검색어 입력란은 처음에 비어 있습니다.** 예시는 별도의 **입력 예시 보기 · 실제 입력값이 아닙니다** 안에만 표시합니다.

- 주제군 이름: 최대 100자
- 검색어: 한 줄에 하나, 각각 최대 200자, 중복 없이 1~5개
- 검색어 추가: 새 줄 입력 또는 유입어 탭의 추가
- 검색어 삭제: 해당 줄을 지운 뒤 저장
- 수정: 저장된 목록의 수정 버튼 → 편집 → 저장
- 삭제: 목록에서 숨기되 기존 버전 이력 유지

저장하면 관리 목록·트렌드 선택 목록·유입어의 대상 목록이 갱신됩니다. 수정 저장 시 새 버전이 생성됩니다. 오래된 버전의 수정·삭제·조회 요청은 거절합니다.

## API 인증정보 숨김 입력 — 더블클릭 실행

**아직 실제 API 조회는 승인되지 않았습니다. 아래 절차로 입력·화면 확인까지만 하고, 실제 조회 버튼은 별도 승인 후 누르세요.**

1. 기존 분석 화면의 **분석 화면 종료**를 누릅니다. 기존 통계 수집기는 종료할 필요가 없습니다.
2. 프로젝트 루트의 **`start_keyword_analysis_secure.bat`를 더블클릭**합니다.
3. 콘솔의 `API HUB Client ID (hidden):`에 Client ID를 입력하고 Enter를 누릅니다.
4. `API HUB Client Secret (hidden):`에 Client Secret을 입력하고 Enter를 누릅니다.
5. **글자와 별표가 보이지 않아도 정상입니다.** 입력은 콘솔에만 합니다. 채팅·브라우저 입력란·코드·BAT에 키를 적지 마세요.
6. 브라우저가 열리면 **API 키 설정 확인됨**을 확인합니다. 이는 형식에 맞는 키를 메모리에 읽었다는 뜻이며 네이버 인증 성공을 의미하지 않습니다.
7. 실제 조회 승인 전에는 여기서 멈춥니다. 종료는 분석 화면 종료 또는 콘솔의 Ctrl+C를 사용합니다.

잘못 입력했으면 입력 중 Ctrl+C로 취소하거나 서버 종료 후 다시 실행합니다. 빈 값·공백·줄바꿈이 있는 입력은 거절합니다. 실행 중인 서버가 있으면 키를 다시 입력받아 무시하는 대신, 기존 서버를 종료하라는 안내를 표시합니다.

이 실행기는 **기존 Python의 `getpass`와 Windows 콘솔 숨김 입력**을 사용합니다. PowerShell 실행 정책 변경·관리자 권한·추가 프로그램 설치가 필요 없습니다. 숨김 입력을 보장할 수 없는 파이프·입출력 리다이렉션 등에서는 입력을 받지 않고 중단합니다. 숨김 입력이 일반 표시 입력으로 바뀌는 fallback도 중단합니다.

기존 환경변수 방식과 호환됩니다.

- `NAVER_API_HUB_CLIENT_ID`
- `NAVER_API_HUB_CLIENT_SECRET`

키는 같은 Python 프로세스의 환경변수로 잠시 전달됩니다. 별도 하위 명령행 인자·파일·소스·BAT·Git·로그에 넣지 않습니다. 서버는 메모리에 키를 읽은 뒤, 브라우저를 열기 전에 해당 환경변수를 제거해 브라우저에 상속하지 않습니다. 입력 취소·오류·정상 종료 때도 실행기가 환경변수를 정리합니다. Windows 사용자/시스템 환경변수를 영구 설정하지 않습니다. 재실행할 때는 다시 입력해야 합니다.

기존 `start_keyword_analysis.bat`와 `--demo` 실행은 그대로 유지합니다. 새 안전 실행기의 `--demo`도 입력 없이 모의 모드로 실행할 수 있습니다.

### 메모리·프로세스 노출의 한계

숨김 입력은 화면 에코를 막는 기능입니다. Python 문자열과 환경변수 전달 중에는 키의 평문이 프로세스 메모리에 존재합니다. 참조 제거가 문자열 복사본의 물리적 덮어쓰기를 보장하지 않습니다. 같은 사용자/관리자 권한의 프로세스 검사, 악성코드·키로거, 디버거·메모리 덤프·운영체제 스왑/크래시 덤프까지 차단하지 않습니다. 클립보드로 붙여넣으면 운영체제 클립보드 기록에도 별도 사본이 남을 수 있습니다. 이 실행기는 클립보드 기록을 관리하지 않습니다.

키는 브라우저 JavaScript나 서버 응답에 전달하지 않으며, API 키·인증 헤더·응답 원문을 로그에 출력하지 않습니다. Windows 자격 증명 관리자 저장 기능은 이번 범위에 없습니다.

### 기존 PowerShell 숨김 입력 방식 — 대안

긴 명령을 복사하지 않으려면 위 안전 실행 BAT를 사용하세요. 아래 방식도 기존처럼 지원하며 실제 키를 스크립트에 적지 않습니다. 새 PowerShell에서 프로젝트 폴더로 이동한 뒤 블록 전체를 실행합니다.

```powershell
Set-Location -LiteralPath 'C:\Users\pri_h\blog-workspace\naver-blog-analytics'
& {
    $analysisIdInput = Read-Host 'API HUB Client ID' -AsSecureString
    $analysisSecretInput = Read-Host 'API HUB Client Secret' -AsSecureString
    $analysisIdPtr = [IntPtr]::Zero
    $analysisSecretPtr = [IntPtr]::Zero
    try {
        $analysisIdPtr = [Runtime.InteropServices.Marshal]::SecureStringToBSTR($analysisIdInput)
        $analysisSecretPtr = [Runtime.InteropServices.Marshal]::SecureStringToBSTR($analysisSecretInput)
        $env:NAVER_API_HUB_CLIENT_ID = [Runtime.InteropServices.Marshal]::PtrToStringBSTR($analysisIdPtr)
        $env:NAVER_API_HUB_CLIENT_SECRET = [Runtime.InteropServices.Marshal]::PtrToStringBSTR($analysisSecretPtr)
        .\start_keyword_analysis.bat
    } finally {
        Remove-Item Env:\NAVER_API_HUB_CLIENT_ID -ErrorAction SilentlyContinue
        Remove-Item Env:\NAVER_API_HUB_CLIENT_SECRET -ErrorAction SilentlyContinue
        if ($analysisIdPtr -ne [IntPtr]::Zero) { [Runtime.InteropServices.Marshal]::ZeroFreeBSTR($analysisIdPtr) }
        if ($analysisSecretPtr -ne [IntPtr]::Zero) { [Runtime.InteropServices.Marshal]::ZeroFreeBSTR($analysisSecretPtr) }
        $analysisIdInput.Dispose()
        $analysisSecretInput.Dispose()
    }
}
```

## 실제 API 최초 조회 — 별도 승인 후

1. API HUB Application에서 검색어 트렌드 권한·현재 요금·한도를 확인합니다. 기존 Developers 키와 혼용하지 않습니다.
2. 안전 실행 BAT로 키를 숨김 입력합니다. 정상 모드와 키 설정 확인 배너를 확인합니다.
3. 검색 트렌드 탭에서 `경매 입찰 준비`를 선택하고 어제 이전의 기준 종료일을 고릅니다.
4. **승인된 시점에 검색 트렌드 조회를 한 번 클릭**합니다. 여기서 처음 외부 API 요청이 발생합니다.
5. 14일 결과와 두 구간 비교를 확인합니다. 인증·권한·한도 오류가 나면 반복 클릭하지 말고 API HUB 콘솔을 확인합니다.

## 계산과 데이터 보존

기존 계산 로직은 유지합니다. 한 일간 응답의 앞 7일 평균 A와 뒤 7일 평균 B를 비교하며 지수 차이는 `B-A`, 변화율은 `(B/A-1)*100`입니다. 이전 평균이 **1 이하**면 변화율을 숨깁니다. 이는 공식 임계값이 아닌 UI 기준입니다.

날짜·그룹·지수 누락은 null로 유지하고 차트 선을 끊습니다. 누락된 구간의 평균·차이·변화율을 만들지 않습니다. 0은 실제 제공된 값으로 누락과 구분합니다. 메타데이터 불일치·중복 날짜·범위 밖 지수는 오류로 처리합니다. 기기·성별·연령은 전체, 단위는 일간으로 고정합니다.

기존 `data/analytics.sqlite3`는 `mode=ro`와 `PRAGMA query_only=ON`으로만 조회합니다. 기존 Store·백업·마이그레이션·로그인을 호출하지 않습니다. 주제군은 기존 `data/keyword-analysis.sqlite3`의 topics/topic_versions에 저장하며 스키마를 바꾸지 않습니다.

API 결과는 DB·브라우저 저장소·서비스 워커에 저장하지 않습니다. 명시적인 엑셀 다운로드만 지원합니다. HTTP 응답은 no-store이고 새 조회·조건 변경·새로고침·종료 후 이전 결과를 화면에서 재사용하지 않습니다. 탭 이동만으로는 같은 화면 세션의 결과를 지우지 않습니다.

서버는 127.0.0.1에만 바인딩하고 임시 페이지 토큰과 Host/Origin을 검사합니다. 동시 API 요청은 1개, 최소 간격은 2초이고 자동 재시도는 없습니다. TLS 검증을 사용하며 외부 프록시 환경변수와 리다이렉트는 사용하지 않습니다. API 실패는 기존 통계·주제군을 변경하지 않습니다.

# ChatGPT 분석용 엑셀 다운로드

검색 트렌드 탭에서 기준 종료일을 선택하고 **ChatGPT 분석용 엑셀 다운로드**를 누릅니다.
종료일까지 14일을 대상으로 하며, 유입어 탭의 검색어 필터는 적용하지 않습니다.
미수집 날짜가 있으면 다운로드 전에 확인 안내가 표시됩니다.

- `실제 유입 검색어`: 날짜·원문·유입 비율 원문(%)·원본 순서·원본 XLSX 해시.
- `검색 트렌드`: 현재 조회 결과의 주제군별 일별 상대지수·기간·일간 및 전체 기기/성별/연령 조건·조회 시각. 개별 구성 검색어의 지수가 아닙니다.
- `주제군 및 수집상태`: 현재 저장된 주제군과 트렌드 조회 당시 주제군의 이름·버전·구성 검색어를 구분하고, 날짜별 수집/검색어 없음/미수집 상태를 표시합니다.

## 미리보기에서 ‘경로를 찾을 수 없습니다’ 또는 404가 나올 때

화면 파일은 최신이지만 Python 서버가 예전 코드로 실행 중이면 `/api/weekly/preview`가 404를 반환할 수 있습니다.
브라우저 새로고침이나 탭 닫기는 서버 코드를 갱신하지 않습니다.

1. 필요한 현재 트렌드 결과와 미저장 복사 텍스트를 먼저 보존합니다.
2. 기존 8766 화면의 **분석 화면 종료**를 누릅니다. 기존 DB를 삭제하거나 초기화할 필요가 없습니다.
3. `start_keyword_analysis.bat`를 다시 실행하고 새로 열린 8766에서 복사 텍스트를 붙여넣습니다.
4. 주간 기능에는 API 키가 필요 없습니다. 기존 트렌드도 사용하려면 안전 실행 BAT의 기존 인증정보 입력 절차를 따릅니다.

서버는 시작 시 실행 코드·화면 파일의 해시를 기억하고 `/api/health`의 `build`에 제공합니다.
BAT에서 중복 실행할 때 같은 프로젝트라도 빌드가 다르거나 구버전 응답에 빌드가 없으면 기존 서버를 재사용하지 않고 재실행 안내를 표시합니다.
프로세스를 강제 종료하거나 운영 DB를 변경하지 않습니다. 인증정보·DB·복사 원문은 빌드 해시 대상이 아닙니다.
